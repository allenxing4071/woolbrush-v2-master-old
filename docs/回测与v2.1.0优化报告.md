# WoolBrush v2.1.0 回测与优化报告

日期：2026-09-17 ~ 09-18
版本：v2.0（旧）→ v2.1.0（本次发布，页头显示 `v2.1.0 · 0917-2336`）

---

## 1. 背景与问题

WoolBrush 在 Polymarket 城市"当日最高温"市场上做 NO 方向高位套利：买入远离预期峰值的温度档位 NO（价格 0.95~0.99），等市场结算或价格到 0.999 止盈。收益结构为**小赢大亏**：单笔盈利约 1%~3%，单笔亏损接近 100%，要求胜率 > 98%。

2026-09-16/17 实盘复盘（32 笔）：31 胜合计 +$181，1 败（Denver 88-89°F）-$487，净亏。逐条排查实盘日志（`data/review/*.jsonl`）后确认了以下问题：

| # | 问题 | 影响 |
|---|---|---|
| 1 | LLM 返回 JSON 解析失败（LaTeX 转义、取到错误的 `{`） | 275 次 LLM 调用中 48 次（17%）作废，整轮白跑 |
| 2 | 开仓只按价格上限拒单，不看盘口深度，GTC 全额挂单 | Denver 单成交价被推到 0.999；深度不足时部分成交 + 挂单虚记 |
| 3 | 止损条件要求 bid **且** ask 同时低于阈值 | 单边崩盘时止损不触发 |
| 4 | 前后端持仓不同步 | 后端已平仓，前端反复报 `No position found` |
| 5 | 开仓决策完全依赖 LLM 的偏移规则，无代码硬校验 | Denver：ST 74.7°F、MET 82.8°F 时开 88-89°F NO，实际最高 89.2°F |
| 6 | UI 标签 TP/SL 语义反了 | 用户误读止损位 |

---

## 2. 回测方法

全部使用公开数据，不依赖用户账户。脚本位于 `backtest/`。

### 2.1 数据（`fetch_data.py`）

| 数据 | 来源 | 规模 |
|---|---|---|
| 市场事件、各档位 token、结算结果 | Polymarket Gamma API | 51 城 × 38 天（2026-08-10 ~ 09-16）= 1938 个城市日，全部已结算 |
| 各档位 NO 价格历史（10 分钟粒度） | Polymarket CLOB `prices-history` | 21,318 条序列 |
| 气象站逐小时实测 | IEM ASOS/METAR（与程序 ST 数据源同源，Denver 9/16 复核 89.2°F 完全一致） | 51 站 |
| 历史预报（对应程序 MET） | Open-Meteo historical-forecast | 51 城 |

Polymarket 当前"最高温"市场只有这 51 个城市，正是程序在跑的城市集合；数据库中另外 43 城无市场。

### 2.2 模拟（`simulate.py`）

按线上真实流程逐小时复现（当地 11:00~17:00）：

- ST 观测滞后 1 小时（与线上日志一致：12:00 快照看到的是 10:58 观测）
- MET 峰值 = 决策时刻之后 10~17 点预报最大值
- 买价 ask = mid + 0.005，卖价 bid = mid − 0.005
- 持仓跟踪：bid ≥ 0.999 止盈；bid ≤ SL 止损；否则按结算（赢 1.0 / 输 0.0）
- 每笔 $100 名义，统计笔数、亏损数、单笔收益率

对比的规则变体：

- `old_llm`：复现旧 prompt 的 OFFSET 规则（≤13 点需偏移 ≥3 档，>13 点 ≥2 档，>16 点降温 ≥1 档）
- `hXX_pN_mM`：新代码闸门，XX = 几点起允许"峰值已过"开仓，N = 高出观测最高温档数，M = 高出 MET 峰值档数
- `llm_AND_*`：LLM 推荐 ∩ 闸门 = 实际线上行为

### 2.3 资金层（`portfolio.py`）

把交易流按真实资金约束跑复利：每笔 = 总资产 × f，现金不足则跳单，止盈/结算后释放资金。压力测试：额外把 1%~2% 的盈利单随机翻成 −100%，200 次取中位数与 10 分位。

## 3. 回测结论

### 3.1 规则对比（ask 0.95~0.98，SL 0.5，每笔 $100）

| 规则 | 笔数 | 亏损 | 胜率 | 单笔收益 |
|---|---|---|---|---|
| 旧 LLM 偏移规则 | 834 | 22 | 97.4% | +1.10% |
| 闸门 15:00 版（09-17 下午首发） | 890 | 21 | 97.6% | +1.36% |
| 闸门 16:00 + MET 半档 | 513 | 6 | 98.8% | +2.17% |
| **闸门 16:00 + MET 半档 ∩ LLM（最终）** | **240** | **1** | **99.6%** | **+2.80%** |

前后半段（08-10~08-28 / 08-29~09-16）分开验证，结论一致。

### 3.2 三个关键发现

**发现一：15:00 判定"峰值已过"太早。**
ST 滞后 1 小时，15:00 看到的是 13:58 的数据，大量城市之后仍再升 1~3°C。23 笔亏损中 15:00 开仓占一半以上。推迟到 16:00 后亏损 23 → 10 笔；再要求高出 MET 峰值半档（拦下 toronto 23°C vs MET 22.9 这类擦边单）→ 7 笔。

**发现二：止损 0.95 / 0.90 是负贡献。**

| SL | 总收益（闸门 16:00 版） |
|---|---|
| 0.95 | −$563 |
| 0.90 | +$158 |
| 0.70 | +$639 |
| 不止损 | +$1153 |
| **0.50** | **+$1304** |

askMin 0.95 时买入后 bid ≈ 0.94，SL 0.95 立即触发；0.90 会把大量最终盈利的仓位在 −1%~−10% 处打掉。真正崩盘的单子多为跳空，0.50 的"灾难止损"能救回一部分且不误杀。**之前建议的 SL 0.95 撤回，改为 0.50。**

**发现三：ask 上限是收益率的主杠杆。**

| ask 上限 | 笔数 | 亏损 | 单笔收益 | 盈亏平衡亏损率 |
|---|---|---|---|---|
| 0.995 | 675 | 3 | +1.34% | ≈1.5% |
| 0.99 | 474 | 2 | +1.85% | ≈2.1% |
| **0.98** | **240** | **1** | **+2.80%** | **≈3.0%** |
| 0.97 | 125 | 1 | +3.26% | 样本过少 |

0.98~0.995 之间买入的单子收益 0.5%~1%，风险同样是 100%；砍掉后单笔收益翻倍，盈亏平衡线从 1.5% 推到 3.0%。

### 3.3 反向策略（买 YES）

评估"温度回落后买当前最高温所在档位 YES"：各价格区间 EV 均在 ±0.07 以内，无稳定优势，不采用。

### 3.4 资金层结果（ask ≤ 0.98，$1051 本金）

| 仓位 | 历史回放 | 亏损率压力至 1.4%：中位 / 10 分位 / 回撤 | 压力至 1.9% | 压力至 2.4% |
|---|---|---|---|---|
| 5% | +39% | +26% / +13% / 6% | +19% / +2% | +13% / −3% |
| **10%** | +75% | **+42% / +15% / 12%** | +28% / +3% | +15% / −16% |
| 15% | +89% | +60% / +16% / 17% | +37% / −1% | +17% / −19% |
| 19% | +92% | +55% / +2% / 20% | +26% / −17% | +19% / −30% |
| 25% | +93% | +45% / +3% / 25% | +43% / −19% | +9% / −39% |

- 10% 是稳健点，15% 是收益顶点，19% 以上收益不涨、风险陡增（资金被占满，机会吃不到）。
- 亏损率 ≥ 3% 时任何仓位都亏钱，仓位改变波动、不改变方向。
- 资金受限时放开 LLM 限制以增加单量**不划算**（5% 仓位下 855 笔流 +19% 反而低于 474 笔流 +20.6%，回撤更大）。

### 3.5 与最老版本对照（$1051 本金、10% 仓位）

| | 最老版本（ask ≤ 0.995，无闸门） | v2.1.0 |
|---|---|---|
| 笔数 / 亏损 | 1772 / 31（1.75%） | 240 / 1（0.4%） |
| 单笔收益 | +0.57% | +2.80% |
| 历史回放 | **−16.8%**，回撤 28% | **+74.6%**，回撤 5% |
| 压力 1.4% | 中位 −37%，10 分位 −50% | 中位 +42%，10 分位 +15% |

老版本边际只有 +0.57% 对 −100%，亏损率 1.75% 已贴着盈亏平衡线；且 11:00~15:00 大量开仓占住资金，实际吃到的子集恰好赔光。

## 4. v2.1.0 改动清单

### 4.1 策略参数（`data/toolbar.json` 与代码默认值）

| 参数 | 旧 | 新 |
|---|---|---|
| ASK 上限 | 0.995 | **0.980** |
| ASK 下限 | 0.950 | 0.950 |
| 止损（SL ≤） | 0.500（用户曾改 0.95） | **0.500** |
| 止盈（TP ≥） | 0.999 | 0.999 |
| 仓位 | 10% | 10%（15% 为可选上限） |
| 扫描间隔 | 1h | 0.5h（一轮 3~4 分钟，半点那轮观测更新） |

### 4.2 开仓安全闸（`src/App.tsx` `checkOpenSafetyGate`）

代码级确定性校验，LLM 只负责推荐，最终放行由闸门决定：

- 峰值未到：档位下限 ≥ max(观测最高, MET 峰值, 市场峰值档上限) + **3 档**
- 峰值已过（**16:00 后**且温度不再上升）：档位下限 ≥ 观测最高 + 1 档，且 ≥ MET 峰值 + **0.5 档**
- `or below` 档位、无观测数据一律拒绝
- 每次放行/拒绝写入复盘日志（`safety_gate_pass` / `safety_gate_fail`）

### 4.3 执行层（`src-tauri/src/commands/trade_cmd.rs`、`infrastructure/clob.rs`）

- 盘口解析加入每档数量；下单前逐档累加 ≤ ASK 上限的卖单深度
- 深度 ≥ 目标：全额；50%~100%：只下可吃的量；< 50% 或 < 5 股：跳过并报 `depth_insufficient`，下一轮可重试
- 订单类型 GTC → **FAK**（吃完即撤，不留挂单）；限价为用到的最深一档
- 以交易所回执的实际成交数量/金额记账；`success=false` 的 200 响应正确报错；`delayed` 状态按请求量记账
- `open_position` 接受 `max_price`，实时 best_ask 超过上限即拒单不追价
- 6 个 `plan_fill` 单元测试

### 4.4 稳定性修复

- LLM 响应解析：优先 ```` ```json ```` 代码块 → 回退到最后一个含 `"actions"` 的平衡 JSON → 清理 LaTeX（`$\le$`、`\text{}`）与非法转义；新增单测
- 止损改为 bid 单边触发，连续 3 tick 确认防抖
- 前端 `processCityClose`：后端已平仓的 `No position found` 自动清理本地持仓，其余错误保留重试
- UI 标签 TP/SL 语义修正
- 版本号 2.1.0，窗口标题与页头显示 `v版本 · 构建时间`

### 4.5 未改动（有意）

- LLM prompt：偏移规则比闸门更保守，在资金受限时保留它反而提高单笔质量
- 平仓路径仍为 GTC 挂买一价：止盈本质是挂单等成交，FAK 会漏卖

## 5. 预期与观察纪律

- 对外口径：月化 **+30%~40%**（压力后中位），历史回放 +75% 属样本运气
- 单量约 8 笔/天，100 笔约两周
- 每 100 笔检查亏损数：≤1 正常；2 笔降仓位至 5%；≥3 停机重跑回测
- 观察 `depth_insufficient` 频率：跳单 > 30% 说明单笔金额对盘口偏大，应降仓位而不是放宽 50% 阈值
- 本金 $4500~$20000 可按上表估算；再大需重算滑点

## 6. 后续方向（需先回测）

1. **最低温市场**：Polymarket 同时有 51 城"最低温"市场，逻辑镜像后机会翻倍，但夜间预报误差特征不同
2. **缩短观测滞后**：整点后 5 分钟直接拉 METAR，可能让 15:00 那批单子（回测中占总量近一半）重新变得安全，是唯一不牺牲收益又能提单量的路径

## 7. 复现

```bash
python3 backtest/fetch_data.py --db data/woolbrush.db --start 2026-08-10 --end 2026-09-16 --workers 32
# 规则回测
python3 backtest/simulate.py --sl 0.5 --ask-min 0.95 --ask-max 0.98
# 资金层
python3 backtest/portfolio.py --trades backtest/out/trades_llm_AND_h16_p1_m0.5.csv --capital 4500 --stress 0.01
```
